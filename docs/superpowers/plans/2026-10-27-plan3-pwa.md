# Plan 3 of 7 — iPhone PWA, Supabase and Spending Features Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Next.js PWA (deployable to Vercel, installable on iPhone) on top of a real local Supabase: sign-in,
consent + connect flow with live job progress and OTP/question entry, the "dashboard first" Spend home, Orders,
Ask (analyst agent over the user's own rows) and Accounts — plus the backend pieces those screens need and a
fake-site worker mode so the whole product runs end to end locally without real delivery-app accounts.

**Architecture:** Supabase (local via `npx supabase start`, later the hosted project) provides Auth, Postgres and
Realtime; the PWA reads the signed-in user's rows directly through RLS (tables + `security_invoker` views) and
subscribes to `jobs` changes over Realtime; actions (consent, connect, OTP/answer, refresh, profile, ask) go to the
FastAPI service with the Supabase JWT. The worker gains a fake mode that simulates a delivery app (OTP prompt,
orders) so Playwright end-to-end tests drive the real PWA → API → queue → worker → DB → Realtime loop.

**Tech Stack:** Next.js 15 (App Router) + TypeScript, Tailwind CSS 3.4, `@supabase/supabase-js` 2 + `@supabase/ssr`,
Vitest + Testing Library, Playwright (Node) for e2e, pnpm; backend Python as before; Supabase CLI via `npx supabase`.

**Spec:** `docs/superpowers/specs/2026-10-27-expense-agent-product-design.md`

## Global Constraints

- Screens follow the approved mockups (`.superpowers/brainstorm/*/content/home-layout.html` option A, `connect-flow.html`, `cart-compare.html` option A for Plan 5): card-based iPhone layout, background `#f6f7f9`, cards white with radius 14px, accent green `#0a7c55`, app colours Zepto `#5b21b6`, Blinkit `#f8cb46`, Swiggy `#fc8019`, Zomato `#e23744`, bottom tab bar Spend · Orders · Cart · Ask · Accounts, safe-area padding, system font stack (`-apple-system, "SF Pro Text", "Segoe UI", sans-serif`), amounts as `₹` with Indian digit grouping (`₹1,23,456`), no horizontal scroll at 375px width.
- OTP input uses `inputmode="numeric"` and `autocomplete="one-time-code"`; OTPs and phone numbers are never stored in the browser (no localStorage/sessionStorage/IndexedDB) and never logged.
- Consent text version `"2026-10-27"`; connecting is impossible without stored consent (API already enforces 412).
- The PWA never uses the Supabase service-role key; it uses only `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `NEXT_PUBLIC_API_URL`.
- Users read only their own rows; every new view is `security_invoker = true`; the Ask agent's SQL runs as role `authenticated` with the caller's JWT claims inside a read-only transaction.
- Instamart is not connectable separately (its orders come through Swiggy's feed).
- All work is committed on `main`; never push; no AI attribution in commit messages. No deploy (Vercel/Azure) until all 7 plans are built and verified locally.
- Every existing test keeps passing.

## Review Focus

- A user signs in on two devices and connects on one: the other must see the job progress and the new connection without reload (Realtime on `jobs`/`connections` under RLS). → T8 e2e `connect flow updates live`.
- The OTP screen is left open past the worker's timeout: the UI must show "Code expired — try again" and offer retry, not spin forever. → T8 `test OTP timeout shows retry` (component) and T10 e2e.
- A question (`question_needed`) arrives instead of an OTP: the UI shows the question with a free-text answer box (≤500 chars), not the 6-digit OTP box. → T8 component test `renders question prompt`.
- A user with zero orders opens Spend: empty state with a "Connect an app" call to action, no NaN/₹0-divide errors in "change vs last month". → T7 component test `empty spend state`.
- The Ask agent is asked about another user's data or to modify data: it can only see the caller's rows and any write is refused. → T2 `test_ask_sql_is_scoped_to_caller` / `test_ask_sql_is_read_only`.

**Files:**
- Modify: `server/api.py`
- Create: `server/ask.py`
- Test: `tests/server/test_api_plan3.py`

**Interfaces:**
- `POST /jobs/{job_id}/answer` body `{answer: str (1..500)}` → 204; same ownership/type/status checks as `/otp` but also accepts jobs whose `progress->>'stage' = 'question_needed'`; sends `pg_notify('otp_<id>', answer)` (the worker's prompt waits on that channel for both kinds); never logs the body.
- `PUT /profile` body `{address: str (5..200), display_name: str | None}` → 200 `{address, lat, lon}`; geocodes with `browser.resolve_location` (injectable for tests); stores `profiles(user_id, display_name, address, lat, lon)` (upsert); 422 when geocoding finds nothing.
- `POST /ask` body `{question: str (1..1000)}` → 200 `{answer: str}`; `server.ask.answer(conn, user_id, question, llm=None) -> str` runs the existing `insights` analyst loop but with `run_sql` replaced by `scoped_sql(conn, user_id, query)`: rejects non-SELECT/WITH and multi-statement input; executes inside `begin read only` + `set local role authenticated` + `set_config('request.jwt.claim.sub', user_id, true)` + `set_config('request.jwt.claims', json({"sub": user_id, "role": "authenticated"}), true)` + `set local statement_timeout = '5s'`; max 200 rows; schema text describes `orders`, `order_items`, `item_categories`, `monthly_spend`, `category_spend`, `merchant_spend`.
- `ASK_FAKE=1` (local e2e only): `/ask` skips the LLM and answers deterministically — runs `scoped_sql(conn, user_id, "select site, sum(amount) as amount from monthly_spend group by site order by site")` and returns it as a Markdown table (`| site | amount |`). Refused (startup error) unless `DATABASE_URL` points at localhost, same guard as T4.
- CORS: allow origins from env `CORS_ORIGINS` (comma-separated; default `http://localhost:3000`), methods GET/POST/PUT, headers Authorization/Content-Type.
